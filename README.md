# E-Reseta — E-Prescription for the Philippines

Three portals in one app:

| Portal | Who | What |
|---|---|---|
| **Super Admin** (`/admin`) | You | Reviews PRC licenses, approves / rejects doctors |
| **Doctor** (`/doctor`) | Approved doctors | Writes **Rx** prescriptions → gets a secure shareable link |
| **Patient** (`/rx/:id`) | Anyone with the link | Sees a locked preview, pays via **QR**, prescription unlocks automatically |

Prescriptions follow the Philippine Rx layout: clinic header, **℞**, *Generic (Brand) · Strength · Form · Disp · Sig*,
signature with **PRC / PTR / S2** numbers, generic-name note (RA 6675 / RA 9502) and a Data Privacy Act (RA 10173) notice.

## Stack

- **Client:** Vite · React 18 · Tailwind 3 · React Router 6 · TanStack Query · Zustand · React Hook Form + Zod · Lucide · qrcode.react
- **Backend:** **Supabase** — Postgres + Row Level Security, Auth, private Storage, Edge Functions
- **Payments:** **PayMongo** hosted checkout, signed webhooks, a permanent ledger and doctor payouts — see [docs/payment-flow.md](docs/payment-flow.md)

## Setup

### 1. Supabase project
1. Create a project at <https://supabase.com>.
2. **SQL Editor** → run [`supabase/migrations/0001_init.sql`](supabase/migrations/0001_init.sql).
3. **Authentication → Providers → Email**: for easiest local testing turn **off** “Confirm email”.
   (If it stays on, doctors upload their license from the “awaiting approval” page after confirming.)
4. Create the Super Admin: **Authentication → Users → Add user** (tick *Auto Confirm*), then run
   [`supabase/seed_admin.sql`](supabase/seed_admin.sql) with that email.

### 2. Edge Functions (PayMongo checkout, webhook, payouts)
```bash
npm i -g supabase            # or: npx supabase ...
supabase login
supabase link --project-ref <YOUR-PROJECT-REF>

cp supabase/functions/.env.example supabase/functions/.env   # fill in the PayMongo keys and webhook secret
supabase secrets set --env-file supabase/functions/.env

supabase functions deploy payment-webhook --no-verify-jwt
supabase functions deploy paymongo-checkout --no-verify-jwt
supabase functions deploy paymongo-ops --no-verify-jwt
supabase functions deploy register-doctor --no-verify-jwt
```
Register `https://<YOUR-PROJECT-REF>.supabase.co/functions/v1/payment-webhook` in PayMongo → Developers → Webhooks
(events listed in [docs/payment-flow.md](docs/payment-flow.md)).

### 3. Client
```bash
cd client
cp .env.example .env     # fill VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY
npm install
npm run dev              # http://localhost:5173
npm test                 # unit tests
```

> Testing on a phone: run `npm run dev` (it exposes your LAN IP) and set `VITE_APP_URL=http://<LAN-IP>:5173`.

## End-to-end test
1. `/doctor/register` → submit with a license image → shows **Awaiting approval** on login.
2. `/login` as admin → **Doctor approvals** → open the doctor → **Approve**.
3. Sign in as the doctor → **New prescription** → save → **Copy link**.
4. Open the link in a private window: blurred preview + QR modal.
5. With PayMongo test keys, pick a method, pay on PayMongo's test page → back on the link, the Rx appears by itself.

## Security notes
- The **blur is only cosmetic**. `get_public_rx()` returns a masked payload (no clinical data, no full patient name) until the
  webhook has set `payment_status = 'paid'`. View the network tab to confirm.
- Online payments are marked paid only by `gateway_handle_event()`, executable **only by `service_role`** (the webhook function),
  after the `Paymongo-Signature` HMAC-SHA256 check. It re-checks the amount and handles each event id once.
  Money that cannot be applied is held aside for an admin, never lost.
- Doctors cannot set `role`/`status` (column grants + `review_doctor()` admin RPC). Prescriptions are immutable after creation.
- Licenses are stored in a **private** bucket; only the owner and admin can read (via short-lived signed URLs).
- Prescription IDs are 21 chars from a 64-symbol alphabet generated by `gen_random_bytes` (≈126 bits).
- Never log prescription content (the Edge Functions log only error messages).

## Before going live — please confirm
- **Rate limiting** of the public RPCs (`get_public_rx`, `create_payment_session`): Supabase has no per-RPC limiter built in.
  Put Cloudflare / a WAF rule in front, or move these calls behind an Edge Function with a limiter.
- **Legal / regulatory:** check current PRC, DOH, FDA and PDEA rules on electronic prescriptions (esp. dangerous drugs / S2),
  e-signatures, and medical-records retention, and register as needed with the NPC under RA 10173. This project does not
  assert legal validity of e-prescriptions on its own.
- Delete the old `mock-gateway` function from the Supabase dashboard and unset `MOCK_GATEWAY_ENABLED` if they still exist.
- Switch to PayMongo live keys and register a separate live-mode webhook only after a full test payment, payout and refund.
